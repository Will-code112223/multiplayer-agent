## Key Question 1: What won at the major 2025–2026 hackathons? (Catalog of ~30 winners)

### Takeaway
Across ~30 well-sourced winners from Feb 2025 to Sep 2026, the dominant winning shape shifted from "voice/multimodal spectacle" (early 2025) to "autonomous agent that closes a loop on real work and writes the result back into the system of record" (2026): PRism gates releases, LORE routes org knowledge through 8 agents, Blackbox fixes data incidents and opens a PR, Gitdefender fixes security bugs inside code review, hyperreasoning verifies agent plans against tests. Short in-person events still reward one unforgettable live interaction (GibberLink, FaceTimeOS, Shepherd, Browser Brawl).

### Inferences
- The 2026 corporate-sponsored online hackathons (GitLab, Microsoft, DataHub, Solo.io) converged on the same winning archetype: a multi-agent system that (a) sits inside the sponsor's system of record (MR/PR, catalog, cluster), (b) does the diagnosis AND the fix, (c) writes the result back, and (d) ships with evidence of rigor (43 tests, evidence gate, invariant suite, explainability).
- Short in-person events (ElevenLabs 40h, Browser Use 26h, Cal Hacks ~36h, JetBrains 2 days, Stanford 3h, Good Omen 20h) are won by projects whose demo *is* the product: a phone call to your Mac, two agents chirping at each other, a cane that steers you, two browser agents fighting live.
- Several high-profile winners were solo builders (Tailored Labs, hyperreasoning, Aphasio, all Cua track finishers) — solo is not a disadvantage when scope is tight.

Productivity/dev-tool winners removed a *specific, named* bottleneck owned by a *specific* role (release manager, data on-call, security reviewer, new hire asking "who knows X", permit applicant, repair-shop owner) and demoed it as a closed loop — input event → agent reasoning visible → artifact landing where the human already works (a merge request, an incident banner, a filled permit form) — rather than as a chat window.

### Cited Findings
- **PRism** (Microsoft AI Dev Days 2026): bottleneck = release decision on a PR; the agent "looks at a pull request and asks what could break in the real world" (multi-agent release gate) — [Microsoft Tech Community](https://techcommunity.microsoft.com/blog/azure-events/announcing-the-ai-dev-days-hackathon-winners/4513528).
- **Gitdefender** (GitLab 2026): bottleneck = security findings dying in review; it "spots the bug, writes the fix, and opens the code review" inside the MR flow — [GitLab blog](https://about.gitlab.com/blog/gitlab-ai-hackathon-2026-meet-the-winners/).
- **LORE** (GitLab 2026 grand prize): bottleneck = organizational knowledge loss; router → 8 specialist agents, loop prevention in the knowledge graph, visual dashboard, carbon tracking, CLI with 43 tests — [GitLab blog](https://about.gitlab.com/blog/gitlab-ai-hackathon-2026-meet-the-winners/).
- **DocSync** (GitLab 2026 Anthropic runner-up): bottleneck = stale docs; Detector → Writer → Reviewer agents — [GitLab blog](https://about.gitlab.com/blog/gitlab-ai-hackathon-2026-meet-the-winners/).
- **Project Blackbox** (DataHub 2026 grand prize): bottleneck = data incident triage; localize via lineage → prove root cause against an evidence gate → repair code → run invariant suite → open PR → write incident back to catalog — [DataHub blog](https://datahub.com/blog/meet-the-winners-of-build-with-datahub-the-agent-hackathon/). **Hindsight**: same bottleneck from the on-call angle, output = tags, incident banners, postmortem doc visible in the live DataHub UI — [DataHub blog](https://datahub.com/blog/meet-the-winners-of-build-with-datahub-the-agent-hackathon/); a first-place LinkedIn post from a DataHub SF event describes the same "write postmortems back to the catalog as annotations visible in the live UI" demo move — [LinkedIn](https://my.linkedin.com/in/dextertws).
- **Sentinel** (OpenAI Build Week 2026, Dev Tools 2nd): bottleneck = pre-deploy vulnerability review; static analysis + constrained GPT-5.6 review + Docker-isolated probes of real server behavior — [OpenAI Devs blog](https://developers.openai.com/blog/build-week-winners).
- **hyperreasoning** (JetBrains × Codex 2026, 1st): bottleneck = coding agents committing to one plan; drafts several approaches, a learned controller expands/cuts/verifies against tests — [JetBrains](https://blog.jetbrains.com/ai/2026/04/building-the-future-of-ides-inside-the-first-jetbrains-codex-hackathon/). **Scopecreep** (2nd): bottleneck = hardware bring-up tool sprawl, collapsed into one IDE tool window — same source.

- **SalesShortcut** (Google ADK 2025): bottleneck = SDR grind; multi-agent lead gen → research → proposal → outreach — [Google Cloud blog](https://cloud.google.com/blog/products/ai-machine-learning/adk-hackathon-results-winners-and-highlights).
- **CrossBeam** (Opus 4.6, 1st): bottleneck = California ADU permit process; built in six days by a lawyer with zero code — [Anthropic](https://claude.com/blog/meet-the-winners-of-our-built-with-opus-4-6-claude-code-hackathon); [Medium analysis](https://medium.com/write-a-catalyst/a-lawyer-a-cardiologist-and-a-road-technician-from-uganda-just-beat-500-developers-at-anthropics-6fe127a5e8bc).
- **Kava** (HackMIT 2025 EigenCloud track): bottleneck = filing an insurance claim after total loss; upload documents → claim generated — [Khoury News](https://www.khoury.northeastern.edu/khoury-undergrads-win-three-categories-at-prestigious-mit-hackathon).
- **Wrench Board** (Opus 4.7, 2nd): bottleneck = repair-shop management, built by an ex-repairer — [EdTech Innovation Hub](https://www.edtechinnovationhub.com/news/a-doctor-a-carpenter-and-a-teacher-win-anthropics-global-opus-47-hackathon).

### Inferences
- The recurring live-demo beat in productivity winners is **"watch the artifact appear where I already work"**: an MR opens, an incident banner appears in the real DataHub UI, a permit form fills. Judges can verify it happened without trusting a slide.
- The second recurring beat is **visible reasoning + a gate**: PRism's "what could break," Blackbox's evidence gate, hyperreasoning's controller, Aegis's per-decision explanations. Judges in 2026 rewarded agents that show *why* and *refuse to act without proof* — an answer to the 2025 "demo worked by luck" problem.
- Persona-first framing (lawyer, cardiologist, repairer, on-call engineer, release manager) consistently beat generic "assistant for everyone."

### Gaps
- No source directly describes the on-stage demo script of PRism, LORE, Blackbox or hyperreasoning (these were online hackathons judged from video/repos); the live-demo observations above rest on in-person winners (FaceTimeOS, GibberLink, Good Omen, Opus 4.6 finals at SHACK15).

## Key Question 3: What do judges and organizers say separated winners from the rest?

### Takeaway
Judges' published notes converge on five separators: (1) state the problem first and make judges feel it; (2) pick what is *newly buildable now*, not the newest tool; (3) scope to one feature and make the demo the centerpiece, rehearsed and de-risked; (4) show domain knowledge — 2026 winners were disproportionately non-engineers with deep problem knowledge; (5) show rigor (tests, benchmarks, gates), because "AI is table stakes."

### Cited Findings
- JetBrains × Codex judge notes (June 2026): the author says "the few minutes teams spent presenting" decided most winners, not the previous day's work. Jono Bacon (Stateshift): "Say what the problem is that you're solving" and get judges to share the frustration. Avi Press (Scarf): presenters often skip the problem because they're excited about the tech. Bonnie Xu (OpenAI): start from something buildable now that wasn't feasible before, not the newest tool — [JetBrains blog](https://blog.jetbrains.com/ai/2026/06/how-to-win-a-hackathon-notes-from-the-judging-table/); further tips (scope to one feature, demo within 90s, pre-fill/mocks, rehearse aloud, simple+clear beats complex+confusing) per [daily.dev summary](https://daily.dev/posts/how-to-win-a-hackathon-notes-from-the-judging-table-wttxezbgq).
- Browser Use founding engineer Reagan Hsu (won prizes at YC, MIT, Stanford, UCSD; YC hackathon win led to his job): "The most important aspect of a project is that it actually serves a purpose"; build from personal pain — "You automatically have a valid pain point, an idea of how to solve it, and a customer: yourself"; "Talk to sponsors. They have good ideas on what projects are boring versus innovative"; don't study past projects or force originality — ask "What do I wish existed that currently doesn't?" — [Browser Use guide](https://browser-use.com/posts/how-to-win-hackathons); [Browser Use on X](https://x.com/browser_use/status/2027917285374189577).
- Cua (Hack the North 2025) replaced subjective judging with a public benchmark (OSWorld-Tiny on HUD) and rerun verification; only 5 of ~30 finished; the binding constraint was inference credits — [Cua blog](https://cua.ai/blog/hack-the-north).
- Anthropic/Opus 4.6: four of five winners were not professional developers; a lawyer, a cardiologist and a Ugandan road technician won — [Anthropic](https://claude.com/blog/meet-the-winners-of-our-built-with-opus-4-6-claude-code-hackathon). Analyst takes: the shared edge is domain knowledge, not code ("none of them were developers") — [2nd Order Thinkers](https://www.2ndorderthinkers.com/p/a-lawyer-just-beat-500-developers); "the limiting factor is how precisely you can describe what you want" / "the hard part… is knowing what the system should do" — [Medium](https://medium.com/write-a-catalyst/a-lawyer-a-cardiologist-and-a-road-technician-from-uganda-just-beat-500-developers-at-anthropics-6fe127a5e8bc); [Hadley Lab](https://hadleylab.org/blogs/2026-03-22-the-lawyer-who-won). Note the "beat 500 developers" headline is a widely syndicated exaggeration — same Medium source.
- Opus 4.7 organizers: winners "combined multi-agent orchestration, persistent memory, MCP tools, sandboxed execution, and smart prompt[ing]" — [ClaudeDevs on X](https://x.com/ClaudeDevs/status/2049644696260235413).
- Judge-then-competitor account across two AI hackathons (100+ devs): successful teams "used AI strategically rather than universally, invested in proper tooling and documentation, and never lost sight of their actual users' needs" — [Medium](https://medium.com/@silverlong326/2-weeks-2-ai-hackathons-100-developers-c7d9933ba092).
- Stanford × DeepMind host: 1st-place app came from a game designer who "has never written production code"; the deciding factor was shipping a working app inside a 3-hour window — [Medium (host, non-independent)](https://medium.com/@elviraux/the-people-winning-ai-hackathons-in-2026-arent-the-strongest-engineers-anymore-3fc43f1d13d7).
- GitLab emphasized shipped rigor in its grand-prize description (router, loop prevention, dashboard, carbon tracking, CLI with 43 tests) — [GitLab blog](https://about.gitlab.com/blog/gitlab-ai-hackathon-2026-meet-the-winners/). DataHub emphasized a "machine-enforced evidence gate" before any fix — [DataHub blog](https://datahub.com/blog/meet-the-winners-of-build-with-datahub-the-agent-hackathon/).
- Microsoft's rubric scored "technological implementation" among criteria and named concrete platform tools for the DevOps track — [Official rules](https://github.com/Azure/AI-Dev-Days-Hackathon/blob/main/OFFICIAL_RULES.md).
- ElevenLabs judges were "unanimous" on GibberLink among 300+ projects; the winning artifact was a 1-minute demo video that went viral the same day — [ElevenLabs](https://elevenlabs.io/blog/announcing-the-winners-of-the-elevenlabs-worldwide-hackathon); [Wikipedia](https://en.wikipedia.org/wiki/Gibberlink).
- Serial-hacker advice echoed by multiple guides: "focus on one strong idea, and limit yourself to at most three well-executed features. Simplicity wins" — [Medium](https://szeyusim.medium.com/how-i-win-most-hackathons-stories-pro-tips-from-a-serial-hacker-1969c6470f92); "No one wants to see a 100-slide deck as they want to see it work" + bring a backup video — [dev.to](https://dev.to/code42cate/how-to-win-any-hackathon-3i99); whole morning spent rehearsing the pitch credited for a win — [Substack](https://jeremykintana.substack.com/p/how-to-win-at-hackathons).

### Inferences

2026 winners were dominated by multi-agent orchestration with a router/controller, agents embedded in systems of record via MCP (GitLab Duo, DataHub, kagent/kmcp, Microsoft Agent Framework/A2A), computer-use and browser agents judged by benchmarks or arenas, sandboxed execution/verification gates, and coding-agent harnesses (Claude Code, Codex). ## Key Question 5: How do winners of SHORT (8–24h) hackathons differ from multi-week online ones?

### Takeaway
Short events are won by one vivid, physically witnessable interaction built by a tight (often solo or ≤4) team, where the judging panel are founders/investors reacting in the room; multi-week online events are won by complete, tested, multi-agent systems embedded in the sponsor's platform, judged from repos and videos by sponsor engineers, and dominated in 2026 by domain experts using coding agents.

### Cited Findings
**Short / in-person (3h–48h):**

### Gaps
- No source quantifies judging rubrics for short vs long events beyond Microsoft's rules; the contrast above is inferred from the winning artifacts and organizer descriptions.
- No prior SpeedHacks winners (2024/2025) were found, so there is no direct precedent for what speedrun's investor panel picked before.
